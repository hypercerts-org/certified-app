# Codebase review, 19 November 2026

Six reviewers read v2 from different angles: the UI toolkit, visual
consistency, Next.js practice, data/auth/caching, complexity, and security.
Each verified its findings in the code. This document lists what was fixed
on the branch `review/2026-11-19` (21 commits, not pushed), what needs a
decision, and what is left. The standards that came out of it are in the
`review-changes` skill (`.agents/skills/review-changes/SKILL.md`) and the
README's "How it is put together".

All gates pass on the branch: `pnpm lint`, `format:check`, `typecheck`,
`test` (37 tests, 4 new) and `build`, with no prerender errors.

## Fixed

### Permissions and data

- **Each permission check made its own server round trip on a cache miss**
  (`7025f866`). The membership cache is per session, but a miss (every five
  minutes) made each of about eight gates on a profile page restore the
  OAuth session and call CGS, queued behind a lock. The checks now run once
  per request. Switching accounts no longer restores OAuth, and "acting as"
  falls back to your own account when memberships can't be read, instead of
  trusting the cookie.
- **One path for "my organizations"** (`e4a41faf`). The account menu's API
  route restored OAuth on every request; each organization took its own 3–4
  API calls. Both lists now use the cached memberships and one batched
  lookup. "Your groups" says when it can't load, instead of "you don't
  belong to any group".
- **A profile save didn't refresh the page at its handle** (`05fd9c23`):
  only `/{did}` was expired. Also: one less API call per organization
  profile (the location comes with the organization).
- **Ask the API the question** (`145fd519`). "Do I follow this account"
  loaded 100 follows and was wrong past 100; it's one lookup now. The
  workspace's endorsement counts used a page capped at 100; they use the
  API's totals, the same numbers the profile shows.
- **Network counts** (`746be3b2`): each kind cached on its own, so one
  failing listing no longer stores "—" for all of them for hours.
  Endorsements are an exact total in one call.

### Security

- **Login CSRF** (`9001cb23`). A plain link to `/oauth/handle-login` with a
  handle on an attacker's server could sign a visitor in to the attacker's
  account (that server approves without asking), and their next edits went
  there, signed by the app. The link now asks "Continue as @handle?" and only
  a same-origin POST starts the sign-in.
- **A profile could be shown under someone else's domain** (`05fd9c23`).
  The API resolves handles one way, so a domain pointed at a victim's DID
  served (and cached) the victim's profile at the attacker's address. A
  profile now shows only at a handle verified both ways.
- **URLs from records** (`693c430c`): links must be http(s), images https
  (no tracking pixels over plain http on every visitor). Tested.
- **Valkey keys are namespaced per deployment** (`01c7fe36`), so a sign-in
  on a preview can't replace the production session of the same account.
  See "Needs your decision" for the part code can't fix.
- **Headers** (`5d474b92`): `nosniff` and a `Referrer-Policy` on every
  response.

### Next.js

- **Workspace pages check access themselves** (`62c6b724`). The check was
  only in the layout; Next's guide is explicit that a layout doesn't keep a
  page's data out of the response. Signed out, a workspace's project links
  were in the HTML. Harmless for public data, wrong as a pattern to copy.
- **Prefetching** (`5f1121a8`). Every row and card prefetched its whole
  destination: one server render per visible row, up to 100 on a followers
  page. Lists now prefetch on hover, focus or touch (Next's documented
  pattern); tabs and the sidebar still prefetch fully. Public data stays in
  the browser for five minutes (was one), which puts it in the shell every
  link prefetches, so pages open complete. Your own saves still refresh at
  once.
- **Outages and unknown pages** (`24d66940`, `41fa79dd`). A Valkey or API
  failure in the header failed every page, public ones included; it now
  shows the signed-out navigation. `/favicon.ico`, `/robots.txt`, bot
  probes and mistyped handles each rendered "Something went wrong", uncached,
  with an API call; they're a cached "Not found" now, with a styled page, a
  real icon and robots.txt.
- **`/` redirects before rendering** (`5d474b92`): a real 307 instead of a
  page with a one-second meta refresh.
- **Catch blocks swallowed Next's signals** (`21a2571e`), which showed as
  prerender errors in the build and could put a signed-out answer into the
  shared shell.

### UI and the toolkit

- **One typographic rule** (`83eb9d49`). The workspace's headings were sans
  (from staging), the profile's serif, and page titles came in three sizes.
  The brand's rule is "do not set a heading in the sans", so: `PageTitle` for
  every page's h1, display-3 for sections, "heading" in boxes and cards,
  `Eyebrow` for labels. The CSS overrides I had appended at the end of
  `globals.css` are merged into the rules they patched, so the Projects page
  rows now match the Overview's.
- **Toolkit where it has the piece** (`7d3f5dcf`, `c58ef8d1`): `MenuButton`
  for "…", `Eyebrow` for labels, `Banner` for failed sections (the field
  error interrupted screen readers), `SearchInput` on the Projects page (the
  old field made iPhones zoom in). Toasts follow the theme; skeletons match.
- **One `ComingSoonButton`** (`23999021`) for the 17 placeholder buttons,
  one size, and screen readers now hear why they're disabled.
- **Dead code** (`46b00f4e`): the badge-awards data layer (about 170 lines
  with no caller), an unused gate, CSS for classes nothing renders, and the
  landing page's styles for routes v2 doesn't have.

## Needs your decision

1. **Production needs its own Valkey database.** If the Redis database
   attached to the v2 preview in Vercel is also attached to Production, any
   preview build can read production users' sign-in tokens. The new key
   namespace stops collisions, not access. Check the database's environments
   in Vercel before v2 goes to production.
2. **Five-minute browser cache for public data.** Others' edits show up to
   five minutes late on in-app navigation (a reload is fresh). This is what
   makes navigation instant; say if you'd rather have one minute.
3. **The workspace overview's look.** Its headings are serif again
   (brand rule over the staging look). The staging-sized rows, square
   avatars and unframed empty state are kept through the "bridged" rules,
   to be replaced by toolkit props (`docs/toolkit-gaps.md`).
4. **TECH-920** (strong references in projects), filed yesterday, still
   decides how project pages resolve edited activities.

## Not fixed yet

Ordered by value. Each is in the reviewers' notes; none is urgent.

- **Toolkit additions** in hypercerts-design: `Avatar`/`IdentityRow` shape
  and size, `EmptyState variant="plain"`, `NavTabs`, `Button
  unavailableReason`, and the rest of `docs/toolkit-gaps.md`. Then remove
  the bridged CSS.
- **API requests** for the API team: a count endpoint (the landing page
  still pages up to 1,000 per kind, and one bad project record makes the
  Projects count fail), handles in actor views (the app resolves every
  handle itself), and `swapRecord` on CGS `putRecord` (two admins saving at
  once can overwrite each other).
- **Navigation defined three times** (`site-nav`, `sidebar-nav`,
  `workspace-nav`): one list of destinations and one nav item component.
- **Shared formatting**: count formatting and plurals are written five ways.
- **Route helpers** (`actorHref` and friends) live in `components/cards.tsx`
  and are imported by server code; move to `src/lib/routes.ts`, and replace
  path regexes with `useSelectedLayoutSegment`.
- **The four profile list pages** (followers, following, endorsements,
  given) are copies of each other.
- **Embeds** take the author as a query parameter, so they can't be cached;
  a path parameter would let the CDN serve partner iframes.
- **A DID profile URL** (`/did:…`) answers 200 with a meta redirect; add a
  canonical link or redirect it in the proxy.
- **Signing out** can, in a narrow race, revoke tokens another browser just
  received.
- **landing.css** still maps staging's tokens onto the design system's and
  four lint rules are relaxed for the ported landing components.
- **Dark mode**: the theme supports it, the app never turns it on. A product
  decision.
